# 子代理与搜索给的「事实」，写进代码前必须实测

子代理、WebSearch、文档摘要**会编造字段名、参数名、协议细节**，而且编得很像真的——有表格、有类型、有默认值。

**规则**：任何来自子代理/搜索的 API 字段名、配置键名、协议细节，在写进代码之前必须真机验证。验证成本通常是几分钟；错了的成本是整条链路重做。

**溯源**（2026-07-12, s-1）：
子代理声称 Claude Code 的 statusLine stdin 包含 `context.tokensUsed / tokensLimit / percentUsed`，还给了完整的 JSON schema。我据此设计了整个上下文报告链路。

实测真相：**这三个字段根本不存在**。statusLine 只提供 `transcript_path`，占比必须自己解析 transcript 算出来（`ccstatusline` 等工具正是这么做的）。

幸好在写代码前顺手验了一下。如果直接下笔，会得到一个永远读不到数据、且原因极难定位的状态栏。

**为什么这条只能是软规则**：它是行为约束，不是可以用代码判定的模式——没法写成校验器。这类规则才应该写在这里；能写成校验器的，去写校验器。
