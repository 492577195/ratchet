# 棘轮：让同类错误在逻辑上无法重演

在聊天框里说「以后别这样」是**没有约束力的**。会话一重置，那句话就不存在了，同样的坑会再踩一遍。

所以：每次失败，都必须转化成系统层面的永久约束。这个动作叫棘轮。

## 第零步：失败可能已经在等你了

起手简报会顶出这样一行：

```
⚙️ 3 条 guard 命中未棘轮化（slopsquatting·sudo）→ /ratchet:ratchet 转化，或驳回
```

那是 `guard` 每次拦截时写下的记录（`.ratchet/hits.jsonl`）—— 机器写的，零歧义。
**命中不等于该写规则**，但它是一个「这里发生过什么」的硬信号，值得看一眼再决定。

`ratchet-audit --root . ` 看全貌。

## 第一步：定位真正的失败

不是「表面出了什么错」，是**哪一步的判断出了问题**。

问：如果重来一次，最早在哪个节点能避免？那个节点就是约束该加的地方。

举例，一个真实案例：
- 表面：上下文占比显示成了 156%，荒谬
- 直接原因：靠模型名猜上下文窗口，猜错了
- **真正的失败**：transcript 里根本没有窗口信息，这是个环境属性——我在没有事实依据的情况下用启发式猜了一个关键数值
- 约束该加在：**任何来自推测的关键数值，都要么显式配置，要么有兜底保护**

只修表面（把 200k 改成 1M）就是没学到东西——换个模型又会错。

## 第二步：能写成校验器吗？

**这是首选，几乎总是。**

| 能写成校验器 | 只能写成规则 |
|---|---|
| 可以用代码判定的（命令模式、文件路径、数值范围、schema 约束） | 需要语义判断的（"要诚实"、"先调研再动手"） |
| **不占上下文** —— 代码不进模型的注意力预算 | **占上下文** —— 每次会话都要读一遍 |
| 拦不住就是 bug，可测试 | 靠模型自觉，会退化 |

如果能写成校验器：

1. 加到 `bin/` 下对应的校验器里（危险动作 → `ratchet-guard`；状态约束 → `schema/state.schema.json`）
2. **给规则一个 id**（命中会被统计，供后续减法审计）
3. **加回归测试** —— 在 `test/run.sh` 里写一条永远拦住它的断言
4. 跑 `./test/run.sh` 确认真的拦住了

没有测试的约束不算约束。

## 第三步：确实只能写成规则的情况

写进 `.ratchet/rules/<主题>.md`，而不是往宪法里塞。

**规则必须带失败溯源**，否则半年后没人知道它为什么存在，也就不敢删：

```markdown
## 子代理返回的字段名必须实测

子代理和搜索会编造 API 字段名。写进代码前必须真机验证。

**溯源**：2026-07-12，agent 声称 statusLine 的 stdin 含 `context.percentUsed`，
据此设计了整个上下文报告链路。实测发现该字段根本不存在。
```

**规则文件按主题分，不要堆成一个大文件** —— 大文件没人读完，等于没写。

## 第四步：宪法满了怎么办

`.ratchet/constitution.md` 硬上限 **4 KB**。满了**必须先删一条才能加一条**。

这不是刁难，是设计：一份没人读完的宪法等于没有宪法。规则膨胀会稀释注意力，让**所有**规则都更容易被忽略——包括重要的那些。

删哪条？跑 `/ratchet:slim` 看审计数据。优先删：长期没再犯的、已经被校验器覆盖的。

## 第五步：让提示闭嘴（棘爪必须能松开）

如果这次是从起手简报的命中提示来的，处理完要标记掉，否则它会一直顶在那儿：

```bash
ratchet-audit --ack <规则名>      # 已转化成校验器，或看过后判定不值得写规则
```

**判定「不值得」也是一个正当结论** —— 不是每次命中都该长出一条规则。
但提示必须有一条消失的路：一个永远挂着的提示会被学会无视，而被无视的提示比没有更糟，
它照样吃掉注意力预算，却不产生任何约束。

别把 `--ack` 当消音器用。它记的是「你看过并做了判断」，不是「你把它藏起来了」。

## 第六步：确认棘轮真的咬住了

告诉用户：

- 加了什么约束，加在哪一层（校验器 / 规则 / schema）
- **为什么是这一层**（能机器化就不该写成文字）
- 怎么验证它真的生效了（测试跑过了吗）
- 如果这次是替换了旧规则，**旧的那条删了没有**

最后一条最容易漏。棘轮只进不退就是熵增引擎。
